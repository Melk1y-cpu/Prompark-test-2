# Промышленный парк «Элгрант Пестрецы»

Адаптивный сайт на HTML/CSS/JavaScript и сервер формы на Python 3.12+. Сторонние пакеты и сборка не нужны. Изображения, фирменный знак, карта, генплан и исходная презентация находятся в `assets/`.

## Запуск

Используйте существующую рабочую копию, отдельный Git worktree не требуется:

```sh
cd /workspace/Prompark-test-2
python3 server.py
```

По умолчанию сервер слушает 127.0.0.1:3000. Для доступа через инструменты облачной среды установите `HOST=0.0.0.0`. Это сервер разработки. На публичном сервере нужен HTTPS reverse proxy с ограничением размера запросов, таймаутами и защитой от частых обращений. Прокси должен направлять и сайт, и `POST /api/contact` в один backend. Для обычного статического хостинга необходим отдельно развёрнутый обработчик и same-origin маршрут `/api/contact`; один `python -m http.server` отправку не поддерживает.

## Почта

Получатель заявок: **Iv08dem@yandex.ru**. Укажите его в переменной `CONTACT_TO_EMAIL` процесса backend. Адрес отправителя настраивается отдельно: наличие адреса получателя не предоставляет доступа к его почте.

Образец параметров — `.env.example`. Это справочный файл: сервер автоматически его не загружает. Настраивайте переменные через секреты/настройки хостинга или менеджер сервисов. Не публикуйте пароли в репозитории и не присылайте их в чат.

| Переменная | Назначение |
| --- | --- |
| `CONTACT_TO_EMAIL` | Получатель: Iv08dem@yandex.ru |
| `SMTP_HOST` | SMTP-сервер отправителя |
| `SMTP_PORT` | 587 для STARTTLS или 465 для SSL |
| `SMTP_MODE` | `starttls` (по умолчанию) или `ssl`; незашифрованный SMTP запрещён |
| `SMTP_FROM_EMAIL` | Подтверждённый почтовым провайдером адрес отправителя |
| `SMTP_USERNAME` | Имя пользователя SMTP |
| `SMTP_PASSWORD` | Пароль приложения/SMTP: только в защищённых настройках backend |
| `PUBLIC_ORIGIN` | Публичный адрес сайта, например `https://park.example`, без завершающего пути; обязателен за HTTPS reverse proxy |
| `HOST`, `PORT` | Интерфейс и порт сервера; по умолчанию 127.0.0.1:3000 |

Для отправки из Яндекс Почты стандартные параметры: `smtp.yandex.ru`, порт `465`, режим `ssl`, полное имя ящика в `SMTP_USERNAME` и тот же адрес в `SMTP_FROM_EMAIL`. В аккаунте отправителя необходимо разрешить SMTP и создать пароль приложения для почтовой программы. Не используйте основной пароль аккаунта.

SMTP требует исходящего TCP-доступа к почтовому серверу. В текущей облачной среде TCP-разрешения не настроены, SMTP-учётные данные отсутствуют. Одного добавления домена в HTTP allowlist недостаточно. Реальную доставку необходимо проверять после подключения SMTP на хостинге с соответствующим сетевым доступом. Proxy-секреты, подставляемые только в HTTPS-запросы, не заменяют настоящий пароль SMTP в окружении backend.

## Поведение формы

Форма отправляет имя, телефон/email, выбранную площадь, направление деятельности, сообщение и подтверждение согласия на обработку данных. Обработчик проверяет поля повторно, ограничивает запрос 12 КБ, применяет ловушку ботов и лимит 5 обращений за 10 минут с одного адреса. При работе за прокси настройте дополнительный IP rate limit на доверенном прокси: backend намеренно не доверяет произвольным `X-Forwarded-For`.

Письмо содержит контакт клиента; для email-контакта устанавливается `Reply-To`. Подтверждение появляется только после принятия письма SMTP-сервером. Это не гарантия попадания во входящие: при подключении проверьте реальный ящик и папку спама. При ошибках поля сохраняются. Повторная отправка во время выполнения блокируется. Нет автоматических повторов после таймаута.

Без SMTP-настроек сервер возвращает 503 с предложением позвонить; успех не имитируется. Сообщения не записываются в локальную базу или логи. Служебные файлы, `.env` и Git-метаданные не раздаются веб-сервером. Сведения об обработке обращений доступны в `privacy.html`; перед публичным запуском оператору следует проверить соответствие текста фактическим процессам.

## Проверки

```sh
node --check app.js
python3 -m unittest -v test_server.py
git diff --check
```

16 серверных тестов проверяют HTTP-маршрут, валидацию, согласие, защиту по origin, лимиты, ошибки и отсутствие SMTP-настроек, закрытые служебные файлы, TLS и сборку письма. SMTP в тестах заменён тестовым транспортом; реальные письма не отправляются. Браузерная проверка проверяет валидацию, сохранение данных при ошибке, реальный ответ 503, состояния отправки и успеха с тестовым ответом, защиту от двойной отправки и мобильный вид. Получение реального письма пока не подтверждено.
